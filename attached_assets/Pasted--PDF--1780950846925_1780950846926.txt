أريد منك إصلاح نهائي وجذري لمشكلة تصدير PDF في نظام السيرة الذاتية.

المشاكل الحالية (حرجة جداً):
- ما زال يتم اختفاء أو فقدان أسطر في نهاية الصفحات أثناء التصدير PDF في جميع القوالب
- يوجد نصوص لا تظهر في بداية الصفحة الثانية
- يوجد نصوص يتم تغطيتها أو إخفاؤها خلف خلفيات بيضاء (white overlays)
- يوجد اختلاف واضح بين Preview و PDF
- المشكلة تظهر في جميع القوالب بدون استثناء

هذا يعني أن المشكلة ليست تحسينات بسيطة، بل خلل جذري في pagination/rendering system.

---

## ❗ شرط العمل الأساسي (صارم جداً)
ممنوع تماماً:
- إضافة أي ميزات جديدة
- أي تحسينات شكلية أو UI
- أي حلول overlays أو تغطية بيضاء كحل للمشكلة
- أي hacks بصرية لتعويض الخطأ

المطلوب فقط:
👉 إصلاح جذري يمنع فقدان أو إخفاء أي نص في PDF بشكل نهائي

---

# 1. Root Cause Analysis (إجباري قبل أي تعديل)

حدد السبب الحقيقي من الكود بدقة، ويجب أن يكون واحد أو أكثر من:

- اختلاف layout بين Preview و Puppeteer PDF rendering
- pageBreak يتم حسابه قبل اكتمال layout النهائي (pre-layout measurement)
- reflow يحدث بعد حساب pageBreaks
- اختلاف font metrics بين بيئة المتصفح و Chromium PDF engine
- overlay system يغطي محتوى حقيقي في بداية/نهاية الصفحات
- overflow hidden أو clipping يقطع أو يخفي عناصر غير محسوبة
- عدم تطابق DOM snapshot بين preview و PDF

❗ ممنوع اقتراح أي حل قبل إثبات السبب من الكود

---

# 2. تحليل تدفق البيانات (Mandatory)

تتبع بدقة:

- أين يتم حساب pageBreaks
- متى يتم قياس العناصر (measurement phase)
- متى يتم تطبيق fonts.ready
- متى يتم توليد HTML النهائي
- ما هو الـ snapshot المستخدم في Preview
- ما هو الـ snapshot المستخدم في PDF

ويجب الإجابة بوضوح:
👉 هل Preview و PDF يستخدمان نفس snapshot 100% أم لا؟

---

# 3. المشكلة الإضافية (CRITICAL BUGS)

يجب إصلاح هذه الحالات أيضاً:

### A. بداية الصفحة الثانية
- أي نص يبدأ في الصفحة الثانية لا يجب أن يُقص أو يُخفى أو يُغطي

### B. White overlay issue
- أي overlay أبيض لا يجب أن يغطي محتوى فعلي
- يجب التأكد أنه لا يوجد content behind overlay غير مرئي

### C. End-of-page clipping
- لا يوجد أي عنصر يُقطع أو يُختفي عند نهاية الصفحة

---

# 4. الحل المطلوب (IMPORTANT)

يجب تنفيذ حل جذري واحد فقط:

## ✔️ Fully Deterministic Snapshot Pagination

المبدأ:
- يتم إنشاء DOM snapshot واحد نهائي فقط
- يتم حساب جميع pageBreaks عليه قبل أي rendering
- يتم تثبيت النتائج (freeze pagination map)
- لا يتم أي recalculation داخل Puppeteer أو أثناء render

❗ ممنوع إعادة الحساب بعد fonts.load أو أثناء PDF generation

---

# 5. شرط التزامن الكامل

يجب ضمان:

- Preview و PDF يستخدمان نفس pagination result 100%
- نفس break positions بدون أي اختلاف
- نفس layout snapshot
- لا يوجد أي divergence بين العرضين

---

# 6. Page Break Rule النهائي (صارم)

if (currentY + elementHeight + 15px > PAGE_HEIGHT)
→ move FULL element to next page

ممنوع:
- تقسيم عنصر
- قص عنصر
- إعادة ترتيب بعد اتخاذ القرار
- أي تعديل بعد مرحلة الحساب

---

# 7. منع فقدان النص (CRITICAL FIX)

يجب التأكد من:

- لا يوجد clipping في بداية أو نهاية الصفحات
- لا يوجد subpixel rendering loss
- لا يوجد overlap between pages
- لا يوجد text hidden behind overlays
- لا يوجد mismatch بين computed height و rendered height

---

# 8. شرط النجاح النهائي (Zero Tolerance)

لا تعتبر المهمة منتهية إلا إذا:

✓ لا يوجد أي نص مفقود أو مختفي
✓ لا يوجد نص مخفي خلف أي عنصر
✓ لا يوجد split line بين الصفحات
✓ Preview = PDF بنسبة 100%
✓ جميع القوالب تعمل بنفس النظام بدون استثناء
✓ تم اختبار 4+ صفحات بدون أي خطأ

---

# 9. إثبات الإغلاق الإجباري

يجب تقديم:

- root cause من الكود مع دليل واضح
- شرح أين يحدث mismatch
- إصلاح واحد جذري فقط (not multiple patches)
- اختبار فعلي يثبت عدم فقدان أي نص

---

## ❗ إذا لم يتم الحل فعلياً
يجب العودة للتشخيص وعدم اعتبار أي تحسين أو تعديل كحل نهائي
